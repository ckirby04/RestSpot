# Seed data

SQL files that pre-populate RestSpot before crowdsourcing begins. They're generated by
[`tools/osm-import`](../../tools/osm-import) from OpenStreetMap.

| File | Area | Contents |
|---|---|---|
| `osm-nwa.sql` | Northwest Arkansas (Fayetteville, Springdale, Rogers, Bentonville) | Mapped restrooms (`source = osm`) plus places that very likely have one (`source = poi_inferred`) |

## Loading into Supabase

1. Apply the migrations first (`supabase/migrations`).
2. Open **Supabase → SQL Editor**, paste the file's contents, and run it.

The script is idempotent: running it again refreshes untouched OSM listings and adds new ones, but
never overwrites a listing a user has verified or edited.

## What gets imported

- **Mapped restrooms** (`amenity=toilets`, or any place tagged `toilets=yes`): name, access, fee,
  hours, and men's/women's/all-gender rooms with wheelchair and changing-table info where OSM has it.
- **Likely restrooms** (`--likely`): real places of kinds that nearly always have restrooms — rest areas,
  travel stops, public libraries, malls, gas stations, and major chains (see `LIKELY_CHAINS`). No room
  details are invented; they show as *"likely has a restroom (not confirmed)"* until a user verifies them.

Every imported listing starts **unverified**.

## Regenerating

```bash
npm run import -w @restspot/osm-import -- --preset nwa --likely --out ../../supabase/seed/osm-nwa.sql
```

Use `--bbox south,west,north,east` for other areas. The public Overpass API is free but
rate-limited; the importer backs off and retries automatically.
